# Linkora — منصة صفحات شخصية وروابط متعددة المستخدمين

مشروع ويب ثابت (HTML/CSS/JavaScript ES Modules) متصل بـ Supabase كخدمة خلفية. كل شخص يمكنه إنشاء حساب، تصميم صفحة شخصية، إضافة روابط، اختيار الألوان والحركة، التحكم في ظهور المعلومات الشخصية، نشر رابط قابل للمشاركة، ثم العودة لتعديل الصفحة لاحقًا. يوجد أيضًا Dashboard منفصل للمدير لمتابعة الحسابات والصفحات ورسائل الدعم.

## مميزات المشروع

- صفحة رئيسية تعريفية متجاوبة مع أنيميشن هادئ ووضع فاتح/داكن.
- تسجيل حساب / دخول / تأكيد بريد / استعادة كلمة مرور.
- إنشاء بروفايل لكل مستخدم باسم مستخدم فريد.
- محرر مباشر يعرض معاينة أثناء تعديل الاسم والوصف والصورة والروابط.
- رفع الصور إلى Supabase Storage (حد 5 MB في إعدادات SQL).
- معلومات إضافية اختيارية: تاريخ الميلاد (الزوار يرون العمر فقط إذا وافق المستخدم)، الطول، الوزن، المكان، الدراسة/الوظيفة. يمكن إظهار كل حقل أو إخفاؤه بشكل منفصل.
- ست لوحات ألوان، ألوان مخصصة، وضع فاتح/داكن، وثلاثة تأثيرات حركة أو إيقاف الحركة، وثلاثة أنماط للكارت.
- رابط عام بصيغة `p.html?u=username`، وزر نسخ رابط، ورمز QR.
- زر نشر/إلغاء النشر.
- نظام طلبات دعم فني وردود المدير.
- لوحة مدير بها قائمة الأعضاء، البريد المسجّل، حالة النشر، تفاصيل البروفايل، إمكانية نشر/إخفاء صفحة، وإرسال رابط استعادة كلمة المرور، وإدارة تذاكر الدعم.
- الحقول الخاصة في `profile_extras` غير متاحة لزوار الصفحة عبر استعلامات REST العادية. دالة عامة ترجع فقط الحقول التي وافق المستخدم على عرضها؛ وتُرجع العمر بدل تاريخ الميلاد الدقيق.

## ملفات مهمة

```text
index.html                 الصفحة الرئيسية
 auth.html                 إنشاء حساب / تسجيل الدخول / استعادة كلمة المرور
 editor.html               محرر صفحة المستخدم
 p.html                    عرض الصفحة العامة حسب username
 dashboard.html            لوحة مدير المنصة
 assets/css/app.css        التصميم والاستجابة للشاشات
 assets/js/config.js       رابط Supabase + المفتاح العام فقط
 assets/js/core.js         عميل Supabase وأدوات مساعدة
 assets/js/auth.js         المصادقة
 assets/js/editor.js       محرر المستخدم وحفظ بياناته
 assets/js/public-profile.js تحميل الصفحة العامة
 assets/js/dashboard.js    لوحة الإدارة والدعم
 supabase/schema.sql       الجداول والسياسات والـ triggers والـ RPC وStorage
```

## خطوات الإعداد بالترتيب

### 1) أنشئ أو اختر مشروع Supabase

افتح [Supabase](https://supabase.com/) وأنشئ مشروعًا مخصصًا للمنصة. يمكن استخدام مشروع موجود، لكن الأفضل مشروع منفصل حتى لا تتداخل الجداول أو السياسات مع تطبيق آخر. انتظر حتى تصبح حالة المشروع Healthy.

### 2) نفّذ قاعدة البيانات

1. افتح المشروع ثم **SQL Editor → New query**.
2. افتح `supabase/schema.sql` من هذا المجلد.
3. انسخ محتوى الملف كاملًا إلى SQL Editor وشغّله مرة واحدة.
4. تأكد من ظهور رسالة نجاح. السكربت ينشئ الجداول، وRLS policies، ودوالًا، وtrigger للمستخدمين الجدد، وBucket باسم `linkora-avatars`، ويعمل backfill للحسابات الموجودة.

لا تضع `service_role` أو Secret Key في الواجهة أبدًا. دالة `get_public_profile` مصممة لإرجاع الحقول العامة فقط، ولا تعيد تفاصيل البريد أو الحقول الخاصة.

### 3) أضف إعدادات Supabase إلى الموقع

من **Project Settings → API Keys** (قد يختلف الاسم قليلًا حسب واجهة Supabase) انسخ:

- Project URL
- Publishable key أو `anon` key العام للمشروعات القديمة

افتح `assets/js/config.js` وغيّر القيم:

```js
window.LINKORA_CONFIG = {
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  supabaseKey: "YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY",
  projectName: "Linkora"
};
```

المفتاح العام متوقع وجوده في تطبيق المتصفح؛ أمان البيانات يعتمد أيضًا على RLS والسياسات في `schema.sql`. لا ترفع كلمة مرور، Secret Key أو `service_role` إلى GitHub.

### 4) ارفع الملفات إلى GitHub

1. أنشئ Repository جديدًا، مثل `linkora`.
2. ارفع **كل محتويات** هذا المجلد إلى جذر المستودع، لا ترفع ZIP نفسه. يجب أن يكون `index.html` في الجذر.
3. في GitHub افتح **Settings → Pages**.
4. في Build and deployment اختر **Deploy from a branch**، والفرع `main` والمجلد `/(root)`، ثم Save.
5. انسخ رابط الموقع الذي يعرضه GitHub Pages.

للتجربة محليًا، لا تفتح ملفات HTML مباشرة بصيغة `file://`؛ استخدم VS Code Live Server أو أي خادم ملفات محلي لأن المشروع يستخدم JavaScript Modules.

### 5) اضبط روابط المصادقة

في Supabase افتح **Authentication → URL Configuration**.

- اجعل **Site URL** هو عنوان GitHub Pages، مثل `https://USERNAME.github.io/linkora/`.
- أضف كـ **Redirect URLs** رابط صفحة المصادقة: `https://USERNAME.github.io/linkora/auth.html`.
- للتطوير المحلي أضف رابط Live Server، مثل `http://127.0.0.1:5500/auth.html` إذا كان هذا هو المنفذ الذي تستخدمه.
- راجع إعداد تأكيد البريد الإلكتروني. إذا كان مفعّلًا، المستخدم يحتاج فتح رسالة التأكيد قبل تسجيل الدخول.

استبدل `USERNAME` باسم حساب GitHub و`linkora` باسم Repository الفعلي. يجب أن تطابق عناوين Redirect URL العناوين المستخدمة في التطبيق.

### 6) أنشئ حسابك وامنحه دور المدير

1. بعد نشر الموقع وتهيئة Supabase افتح `auth.html?mode=signup` من موقعك.
2. أنشئ حسابًا بالبريد الذي تريد أن يكون حساب مدير المنصة.
3. أكّد البريد إذا طلب Supabase ذلك، ثم سجّل الدخول مرة واحدة.
4. افتح **Supabase → SQL Editor → New query** ونفّذ الأمر التالي بعد استبدال البريد ببريد حسابك:

```sql
insert into public.platform_admins(user_id)
select id from auth.users
where lower(email) = lower('YOUR-ADMIN-EMAIL@example.com')
on conflict (user_id) do nothing;
```

5. سجّل خروجك ثم ادخل مرة أخرى، وافتح `dashboard.html`. لو لم تظهر صلاحية المدير، تحقق من أن البريد صحيح وأن الأمر تم تنفيذه على مشروع Supabase الذي يشير إليه `assets/js/config.js`.

**لا تسمح للمستخدمين بتعديل جدول `platform_admins` من واجهة الموقع.** إضافة مدير جديد يجب أن تتم يدويًا من SQL بواسطة مالك المشروع.

### 7) ابدأ استخدام المنصة

- الصفحة الرئيسية: `https://USERNAME.github.io/REPOSITORY/`
- تسجيل الدخول: `https://USERNAME.github.io/REPOSITORY/auth.html`
- محرر الصفحة: `https://USERNAME.github.io/REPOSITORY/editor.html`
- لوحة المدير: `https://USERNAME.github.io/REPOSITORY/dashboard.html`
- صفحة عامة: `https://USERNAME.github.io/REPOSITORY/p.html?u=USERNAME_OF_PROFILE`

اسم المستخدم فريد على مستوى المنصة. كل عضو يعدّل ملفه وروابطه فقط، والمدير يمكنه مشاهدة قائمة الأعضاء، تغيير حالة النشر، فتح تفاصيل الحساب وإرسال رابط استعادة كلمة المرور بالبريد. لا يستطيع المدير عرض كلمة مرور أحد أو معرفتها؛ استعادة كلمة المرور تتم عبر البريد الإلكتروني.

## ملاحظات مهمة قبل الإطلاق العام

- GitHub Pages يستضيف ملفات ثابتة؛ لذلك ملف `dashboard.html` نفسه قابل للتحميل حتى لو كان محتواه لا يظهر إلا بعد التحقق من دور المدير. الصلاحيات الفعلية موجودة في Supabase. لو تحتاج منع الوصول إلى ملف لوحة الإدارة نفسه، استضف لوحة الإدارة خلف Cloudflare Access أو خدمة تدعم حماية المسارات.
- صفحة المستخدم تستخدم `p.html?u=username` لتعمل على GitHub Pages بدون إعداد إعادة كتابة المسارات. للحصول على شكل رابط مثل `/username` ستحتاج استضافة أو طبقة توجيه تدعم rewrites.
- لا تنشر بيانات حساسة في وصف عام. حقول الميلاد والطول والوزن مخزنة في جدول خاص وتظهر للزوار فقط حسب خيارات المستخدم. رفع صورة البروفايل يجعل الصورة نفسها عامة إذا كانت الصفحة منشورة، لأنها محفوظة في Bucket عام لتسهيل عرضها.
- هذا المشروع starter متكامل قابل للنشر لكنه يحتاج إضافة مفاتيح Supabase الصحيحة، تنفيذ SQL، ضبط Redirect URLs، وتجربة فعلية في مشروعك. لا يمكن اختبار تسجيل الدخول أو إرسال البريد دون إعداداتك.
- قبل استقبال عدد كبير من المستخدمين، أضف مراقبة/حدود استخدام وراجع سياسات حفظ البيانات، سياسة الخصوصية، وشروط الخدمة بحسب طريقة إطلاق المنصة.

## استكشاف أخطاء شائعة

**`Supabase غير مضبوط`**: راجع `assets/js/config.js` وتأكد أن الرابط يبدأ بـ `https://` وأن المفتاح عام وصحيح.

**`new row violates row-level security`**: تأكد أن `schema.sql` نُفذ بالكامل، وأن المستخدم مسجّل الدخول بحسابه، وأن الـ Repository يشير إلى المشروع الصحيح.

**المستخدم لا يستطيع نشر الصفحة**: تحقق من الجداول `profiles`, `profile_extras`, `profile_links` والسياسات الخاصة بها. في لوحة Supabase تأكد أن الحساب يظهر في Authentication → Users.

**المصادقة ترجع إلى صفحة خطأ أو لا تصل رسالة التأكيد**: راجع Authentication → URL Configuration، وعناوين Redirect URLs، وإعدادات SMTP/Email الخاصة بمشروع Supabase.

**لوحة المدير تعرض Access denied**: نفّذ أمر إضافة بريدك إلى `public.platform_admins`، ثم سجّل الخروج والدخول مرة أخرى.
